## 3. 方案偏差披露（1 项，合理）

**UART1 驱动删除重装**（protocol.c L347–400）：任务包写"bsp 已装驱动，不要重复 install"，实现为 `uart_driver_delete()` + 重装（**带 event queue**）。原因：T2 的 bsp 安装驱动时未带事件队列（queue_size=0、uart_queue=NULL），而事件驱动 RX + 超时检测必须有队列。**这是任务包自身的疏漏**（规划时未预料 bsp 无队列），Agent 处置正确：重装复用 BSP Kconfig 引脚/波特率（单一事实来源未破坏），注释交代了完整理由。运行时行为：bsp_init 尾部发的 "BSP UART1 ready" 在旧驱动实例上完成后才重装，无竞态（单线程顺序执行）。

## 4. 验收标准修正（规划侧错误，与执行方无关）

任务包要求吞吐 ≥3000 行/秒（v1.4 由 5000 修正而来），按 3 字节帧计算上限 3840。但 Agent 发送 `ok\r\n`（4 字节，GRBL 惯例，RX 侧协议本就兼容 `\r\n`，PLAN §4.1 未禁止）→ **TX 物理上限 11520÷4=2880 < 3000，判据再次物理不可达**。连续两次同类计算错误（先 5000 后 3000），根因是判据先于 TX 帧格式定稿。处置：

- **PLAN §4.2 补充定案：TX 侧（ok/error/状态帧）统一 `\r\n` 结尾**
- **T3 吞吐判据改为 ≥2400 行/秒**（上限 2880 的 ~83%，为互斥锁/调度/驱动开销留余量）
- RX 侧定义不变（`\n` 兼容 `\r\n`）
