# MT6835 CS 建立时间实验与固件验证记录

## 环境与范围

日期：2026-10-23。运行环境为 Linux 开发容器、ESP-IDF v6.1、ESP32-S3 rev v0.2，
通过原生 USB-Serial/JTAG 烧录、读取日志及访问调试接口。
硬件接线以[硬件参数](../hardware.md)为准；板载小车编码器位于 SPI2，外接摆角编码器位于 SPI3。
验证时 SPI 配置为模式 3、1 MHz，USB 总线供电约 5 V，电机保持 DISABLED。

验收对象为板载编码器。外摆杆编码器尚未接入，外接通道日志保留用于说明实验条件，
不参与通过判定。有限样本中的成功率只适用于记录的环境、次数和时长，
不代表所有转速、温度、供电和接线条件均已完成验证。

## 问题与行为要求

固件使用 `1010` 连读角度时，两个通道的启动日志均记录全零接收帧。
驱动必须在 CSN 拉低后提供满足器件要求的建立时间，再发送命令；
帧格式、CRC 与角度解释见[读角事务](T4-brief.md)。
SPI 事务返回成功只表示主机完成了传输；器件数据还必须通过帧校验。

## 寄存器对照实验

CPU 暂停后，通过 OpenOCD 访问原有 SPI 控制器。保留模式、时钟和引脚配置，
关闭 DMA（直接存储器访问），改用 SPI 数据寄存器发送读命令。
每个事务都重置收发 FIFO（先进先出缓冲）、清除完成标志、应用配置、启动事务，
待完成后读取接收字节。实验结束后复位，恢复原固件。

第一组实验比较 `0011` 单寄存器读取与 `1010` 连读，CS 建立等待分别取 0、1、2 个时钟周期。
单读分别读取 0x003～0x006，每个地址有独立 CS 周期；连读在同一事务中读取四个字节。
因此单读结果用于判断链路是否能够返回字节，不能用作运动过程中原子快照的替代。

| 通道与操作 | CS 建立等待 | 接收结果 |
| --- | --- | --- |
| 板载通道，`1010` 连读 | 未开启 | 接收六个 `FF`，角度帧 CRC 不符。 |
| 板载通道，`0011` 单读 | 未开启 | 四个寄存器依次返回 `F8 C3 98 2E`。 |
| 板载通道，`1010` 连读 | 1 个周期 | 有效载荷为 `F8 C3 98 2E`，CRC 正确。 |
| 板载通道，`1010` 连读 | 2 个周期 | 有效载荷为 `F8 C3 98 2E`，CRC 正确。 |
| 外接通道，单读与连读 | 0、1、2 个周期 | 所有事务均返回全零；该通道未接传感器。 |

命令和地址发送期间，MISO 为高阻；接收帧前两个字节不参与角度解析。
全零与全 `FF` 都不能单独证明接线状态；有效性由数据与 CRC 联合判断。
原始输出见[单读与连读对照](evidence/2026-10-23-mt6835-spi-cs/command-comparison.txt)。

第二组实验固定发送 `A0 03 00 00 00 00`，将 CS 建立等待关闭与开启 1 个周期交替执行 10 轮。
两种条件下的其他事务配置相同；上位机独立使用多项式长除法核验 CRC。

| CS 建立等待 | 事务数 | 有效帧数 | 成功率 |
| --- | ---: | ---: | ---: |
| 未开启 | 10 | 0 | 0% |
| 1 个周期 | 10 | 10 | 100% |

开启等待后，10 次载荷均为 `F8 C4 58 0B`，CRC 正确。
[交替实验原始输出](evidence/2026-10-23-mt6835-spi-cs/alternating-comparison.txt)
同时记录了实验与复位退出状态。

该对照确认：板载通道的连读失败与 CS 建立等待缺失有关。
实验使用 CPU 控制的 SPI 数据寄存器，还需通过正式固件验证原有 DMA 采样流程。
外接通道未接传感器，两种命令下的全零结果不用于判断板载问题的根因。

## 固件修复

[驱动初始化](../../components/mt6835/mt6835_hw.c)为所有 MT6835 实例配置 2 个 SCK 周期的
CS 建立等待。默认 1 MHz 时等待为 2 µs；项目配置上限 16 MHz 时为 125 ns，
满足器件规定的建立时间。两条 SPI 总线共享这一初始化入口。

## 烧录后验证

### 构建与烧录

在仓库根目录加载 ESP-IDF 环境，并按 ESP32-S3 的 USB 唯一标识选定端口：

```bash
source /opt/esp/idf/export.sh
idf.py -B build -p /dev/serial/by-id/usb-Espressif_USB_JTAG_serial_debug_unit_44:1B:F6:8D:10:EC-if00 build flash
```

执行会话 `69167` 退出码为 0，esptool 完成写入并验证 Flash 数据散列。
[构建输出](evidence/2026-10-23-mt6835-spi-cs/build-output.txt)、
[烧录输出](evidence/2026-10-23-mt6835-spi-cs/flash-output.txt)及
[固件散列与大小](evidence/2026-10-23-mt6835-spi-cs/firmware.json)用于追踪本次产物。
启动日志中的 ELF SHA256 前缀为 `3f4919593`，与构建产物一致。

### 正式任务连续运行

保持正式固件原有 DMA 传输流程，在 CPU1 上对板载实例 `last_fail` 字段设置写监视点。
该字段在初始化完成后的所有 SPI 错误、全零帧和 CRC 错误分支中均会被写入，
成功分支不写入；因此单次失败即可令 CPU 停下，不依赖连续 10 次失败的日志阈值。
先通过 SPI 设备所属控制器的编号确认该实例属于 SPI2，避免把未接入的外接通道计入。

运行时 SPI2 `USER=0x180000c1`、`USER1=0xf8430007`，
CS 建立等待使能位为 1，周期字段为 1（对应 2 个周期）。
监视期间不暂停 CPU，每隔 5 秒查询运行状态；60.016 秒内 CPU 始终运行，
失败监视点未触发，失败快照保持不变。执行会话 `78133` 退出码为 0，
[原始输出](evidence/2026-10-23-mt6835-spi-cs/runtime-watch.txt)保留了寄存器读数和各次查询。
采样任务配置为 1 kHz，本次监视未添加事务计数器，因此不将时长换算为精确成功帧数。

该检查使用 OpenOCD 内置 JTAG 适配器，设置 `ESP_RTOS=none`、`ESP_FLASH_SIZE=0`，
关闭 GDB 服务，并通过 Tcl 端口 16666 控制。板载实例地址和下面的指令地址仅适用于
所记录的 ELF；重新构建后必须重新定位，不能复用地址推断结果。

### 正式 DMA 帧独立校验

在 `mt6835_hw_read_raw` 入口识别板载实例及其输出地址，再在函数返回前设置硬件断点，
通过输出地址过滤外接实例。每次记录栈内六字节 DMA 接收帧、函数返回值及角度和状态输出。
上位机将前三个载荷字节补零后，使用生成多项式 `0x107` 做二进制长除法，
将余数与接收 CRC 比较；该核验不调用固件中的 CRC 函数。
同时独立解析角度和状态，与驱动输出比较，并检查函数返回成功。

执行会话 `96911` 退出码为 0，1000 次板载读帧全部通过上述检查，
有效帧率为 100%，STATUS 均为 0，原始角度均为 `2037903`。
[逐帧输出及汇总](evidence/2026-10-23-mt6835-spi-cs/runtime-samples.txt)
保留每个接收帧和核验结果。抓帧持续 359.585 秒，调试断点会延长采样间隔，
因此本组结果不用于证明 1 kHz 吞吐或运行时序性能；连续运行检查见上一节。

### 重复启动与结束状态

通过同一 USB 唯一标识运行 `idf_monitor.py`，首次连接产生一次 USB 复位，
随后使用 `Ctrl+T`、`Ctrl+R` 再复位四次。五次启动的板载首读均成功，
原始角度依次为 `2037907`、`2037902`、`2037898`、`2037901`、`2037901`；
每次 ELF 散列前缀均与记录的固件一致，日志中没有板载读帧失败或 STATUS 告警，
也没有 panic（固件崩溃）或看门狗异常。此项是保持供电的 USB 复位检查，未进行物理断电。

监视会话 `50187` 正常退出，退出码为 0。
[完整启动日志](evidence/2026-10-23-mt6835-spi-cs/startup-monitor.txt)保留五次启动，
[汇总](evidence/2026-10-23-mt6835-spi-cs/startup-summary.json)记录首读值及实例范围。
日志中的 `me_pole` 全零和 NOT OK 来自尚未接入的外摆杆，不计入板载结果。

抓帧后清除硬件断点、恢复两颗 CPU 并退出 OpenOCD，再进行上述四次重复复位。
结束时正式固件正常运行，电机 EN 保持禁用；串口监视器和调试接口均已释放。

## 验证结论与边界

| 检查 | 结果 |
| --- | --- |
| 正式固件构建与烧录 | 成功，Flash 写入散列核验通过。 |
| 正式 DMA 流程抓帧 | 1000/1000 帧有效，CRC、角度及状态解析均一致，STATUS 均为 0。 |
| 正式任务连续运行 | 60.016 秒内没有任何板载 SPI、全零帧或 CRC 失败记录。 |
| 重复启动首读 | 5/5 次成功，日志没有板载失败或状态告警。 |

本次板载编码器在模式 3、1 MHz、约 5 V 总线供电和静止位置条件下全部通过，
修复前的 `1010` 连读失败未再出现。2 个周期覆盖 16 MHz 配置上限的结论来自时序计算，
本次未实测其他 SPI 频率，也未覆盖全角度运动、高转速、温度变化、物理断电及长期运行。
没有采集示波器波形，因此不把配置周期换算值表述为波形测量结果。
有限样本达到 100% 通过率，不能据此承诺所有工况永久无错误；外接编码器仍需接入后单独验收。
