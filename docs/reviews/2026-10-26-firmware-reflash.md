# 正式固件重新烧录与启动检查

日期：2026-10-26。当前 PCB 已安装到电机后方，尚未接入滑台，外摆杆编码器未接入。
本次通过电脑原生 USB 烧录，UART0 通过 ST-Link VCP 连接电脑，电机保持禁用。

## 当前板子与固件

ESP32-S3 USB 标识为 `44:1B:F6:CA:59:F8`，芯片版本为 v0.2，Flash 为 16 MB，
内置 PSRAM 为 8 MB。该标识与 2026-10-23 验证使用的芯片不同；
本次记录以当前板子的实测结果为准。

正式工程执行 `idf.py -B build build` 成功，构建会话为 `99997`，退出码为 0。
应用为 `cartpole-fw`，ELF SHA256 前缀为 `3f4919593`，与启动日志一致。
本次没有新增源码修改。

## 烧录结果

esptool v5.3.1 通过当前 ESP32 原生 USB 端口写入 bootloader、分区表和正式应用，
三个镜像均通过写入散列校验。烧录会话为 `59124`，其中 esptool 的退出码为 0。
[烧录输出](evidence/2026-10-26-firmware-reflash/flash-output.txt)保留了完整参数和结果。

看门狗复位后，自动采集脚本立即打开 USB 串口时遇到 `ENODEV`，该汇总会话退出码为 1。
错误发生在固件写入、散列校验和复位完成之后。USB 重新枚举后，单独采集启动日志成功，
会话为 `68755`，退出码为 0。

用户在接回电脑 USB 之前测得 PD 母线约 9 V、逻辑电源约 3.3 V；
本次电脑 USB 供电的启动日志记录母线为 4.92 V。
这两组数据对应不同的供电连接，本次启动检查不替代 PD 调档或电机相电流验收。
