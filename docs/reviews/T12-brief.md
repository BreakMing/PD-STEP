## 3. 任务边界

交付一个**上位机侧**的端到端验收脚本：发 G-code、收响应、解析状态帧、判定 PASS/FAIL、写报告。

**不做**：任何固件改动；任何固件侧判断逻辑（D6：失步判断只在上位机/T12 脚本里）；性能调优。

## 4. 脚本规格

### 4.1 命令行

```
python tools/host_sim.py <PORT> [--skip-power-cycle] [--phase {1,2}] [--fast] [--report PATH]
```

| 参数 | 说明 |
|---|---|
| `PORT` | 串口号（如 `COM7`） |
| `--skip-power-cycle` | 跳过用例 7（掉电重启），其余照跑 |
| `--phase 1` / `--phase 2` | 分阶段跑用例 7（见 §5.7）；默认跑全部非断电用例 |
| `--fast` | 缩减用例 2 的段数（如 1000→100），用于快速自检 |
| `--report PATH` | 报告输出路径，默认 `docs/acceptance.md` |

### 4.2 通用要求

- **读超时**：`serial.Serial(..., timeout=0.3)`；逐行 `readline()`
- **响应匹配**：按行读取，**跳过不匹配协议语法的行**（含以 `I (`/`W (`/`E (` 开头的 ESP_LOG 行，防御事实 #1），只认 `ok` / `error:<n>` / `<STATE|...>` / `$n=...`
- **每条命令**：发送 → 等待期望响应 → **超时视为该用例 FAIL**（附原始超时上下文）
- **状态帧解析**：正则 `^<(?P<state>[A-Z]+)\|C:(?P<c>-?\d+\.\d+)\|E:(?P<e>-?\d+\.\d+)\|V:(?P<v>-?\d+\.\d+)\|T:(?P<t>[A-Z0-9]+)>$`
- **运动完成判定**：`?` 返回 `IDLE` 视为静止（配合超时轮询，轮询间隔 50ms）
- **不使用阻塞式 sleep 等待运动结束**，一律轮询 `?`（避免把"等待时长"变成判据）
- **每例输出**：`PASS/FAIL <case>` + 关键数据行（数值evidence）
- **结束时**：汇总 `TOTAL: n/N PASS`，并把完整结果写入报告文件
- 脚本必须**幂等可重跑**：开头 `M17` + `G92 X0` 建立已知基准（并记录；若轴不在行程内应提示）

### 4.3 报告格式（写入 `docs/acceptance.md`）

```markdown

- 日期时间 / 串口 / 固化版本（`?` 不受影响，版本可从 `$$` 与人工核对）
- 环境：正常固件（所有测试开关关闭）
- 结果表：| 用例 | 判据 | 实测 | 结论 |

- 汇总：TOTAL n/N PASS

```

## 5. 用例设计（PLAN T12 节 8 项，全部必做）

> 所有用例的运动行程必须落在软限位内。建议**开头先 `M17` + `G92 X0`**，然后先发一次 `G1 X300 F3000` 把轴带到行程中段，再 `G92 X300` 把该处声明为 300mm —— 此后往复运动的空间就落在 `[298, 302]` 附近，天然安全（事实 #7）。

### 5.1 用例 1 · ok 流控窗口与背压

- 连续发送 **20 行**`;`（注释行，合法且立即回 `ok`）而**不读取**响应
- 然后开始读取，统计收到的 `ok` 数量与顺序
- **判据**：20 个 `ok` 全部收到、无丢失、无错序；过程中无 `error:*`
- 说明：发送量超过固件侧流控窗口（16 行）时，固件应阻塞背压而非丢行；**不要求**脚本精确观测"第 17 行阻塞"的内部行为，只要求**零丢失**

### 5.2 用例 2 · 1000 段混合 F/A 流式执行

- 进入 `G91` 相对模式
- 循环 1000 次：交替发送 `G1 X+2 F<A> A<B>` 与 `G1 X-2 F<A'> A<B'>`（F/A 在若干组取值间轮换，例如 F ∈ {1200, 1800}、A ∈ {200, 500}，**每次显式给出**）
- 每条命令等待 `ok`
- **判据**：1000 条全部 `ok`，无 `error:*`，无超时
- `--fast` 时降为 100 段

### 5.3 用例 3 · 每段静止后 C 与 E 偏差 ≤0.1mm（无失步判据）

- 与用例 2 同一条流；**每段完成后立即发 `?`**，解析 C/E
- **判据**：`|C − E| ≤ 0.1mm`，**全部段满足**；报告给出最大偏差与出现位置
- 说明：这是 PLAN §9"固件不做判断、由上位机判据验证无失步"的落地。允许极少数点因"编码器 1kHz 采样与帧构建的时序差"出现 ~0.02mm 波动，但**不得出现随段数递增的趋势**（若最大偏差出现在末段且显著大于首段，应报 FAIL 并提示"疑似丢步"）

### 5.4 用例 4 · `!` 立即停

- `G90`；发一条长行程（如 `G1 X580 F3000 A60`，约 580mm）
- 运动开始后（等 1~2 秒，确认 `?` 返回 `RUN`）发送**单个 `!` 字节**（不带 `\r\n`）
- 轮询 `?` 至 `IDLE`，记录：
  - 停止时的 `C`（应显著小于目标 580）
  - 再等 500ms 后二次 `?` 的 `C`（**必须与上次完全相同** → 冻结）
- 随后发 `G1 X50 F1200`（**注意：从冻结位置到 50，若冻结位置 < 50 则改为 `G1 X<冻结位置+20>`**），验证：
  - 正常 `ok`、正常运动到目标
  - 最终 `?` 的 `C` ≈ 目标（±0.05mm）
- **判据**：停止后 C 冻结不变；后续命令从冻结位置正常执行（**不得反向狂奔**）
- 对应真机实测参考：C 冻结 301.600mm（目标 1000mm），随后 `G1 X50` 精确到 50.000mm（T10 验收）

### 5.5 用例 5 · F/A 模态省略行为

- `G90`，`G1 X20 F600 A100`（显式 F/A，**记录该段耗时**——用 `?` 轮询 RUN→IDLE 的时间戳差）
- 再发**不带 F/A** 的 `G1 X40`（模态沿用 F600/A100），记录耗时
- 再发 `G1 X60 F2400`（显式改 F，A 仍沿用），记录耗时
- **判据**：
  - 段 1 与段 2 耗时接近（同为 F600：20mm @ 10mm/s ≈ 2.0s + 加减速）
  - 段 3 明显更快（F2400 = 40mm/s）
  - 三者均 `ok`（模态省略不报错）
- 说明：**用耗时对比作为模态生效的间接证据**；阈值建议"段 3 耗时 < 段 2 耗时的 60%"，并在报告中打印三个实测耗时

### 5.6 用例 6 · G92 建零后 C/E 同步平移

- 记录当前 `?` 的 (C₀, E₀)
- 发 `G92 X0` → `?` 应得 `C ≈ 0.000` 且 `E ≈ 0.000`（两者**同时**归零，D10）
- 发 `G92 X123.456` → `?` 应得 `C ≈ 123.456`、`E ≈ 123.456`
- **判据**：两次 G92 后 C 与 E 的**差值保持 ≤0.1mm**，且**各自都平移到位**（不是只有 C 动、E 不动）

### 5.7 用例 7 · 掉电重启参数保持（NVS）

需人工断电，故设计为**两阶段**：

- **阶段 1**（`--phase 1` 或不带阶段参数时执行）：
  1. 读 `$$` 记录 `$5` 原值
  2. `$5=1500`（若原值即 1500 则改用 1400）→ 期望 `ok`
  3. `$$` 复核已生效
  4. **打印醒目提示**：`请断开 12V 与 USB，等待 5 秒后重新上电，然后运行 --phase 2`
  5. 报告写入"阶段 1 完成，待断电重启"
- **阶段 2**（`--phase 2`）：
  1. 读 `$$`，验证 `$5` == 阶段 1 设定值 → **PASS**（NVS 持久性）
  2. 恢复原值并复核
- **判据**：阶段 2 读到的 `$5` 与阶段 1 写入值**严格相等**
- `--skip-power-cycle` 时跳过并计入"未执行项"
- **不得**尝试用 `G92`/软复位替代真实断电（T11 教训：reload 会掩盖冷启动缺陷，必须真断电）

### 5.8 用例 8 · 遥测帧频率、格式与 T 旗标

- 读 `$9` 取 report_hz（默认 10）
- 发一条**足够长**的运动（如 `G1 X400 F1200 A200`，约 20s），在运动期间**只监听不发送**，连续记录状态帧 2 秒
- **判据**：
  - 帧数 ≈ `report_hz × 2`（容差 ±2）
  - **每一帧**都匹配 §4.2 的正则（格式合法）
  - 帧内 STATE 为 `RUN`
  - `T` 旗标为 `OK`（硬件正常时应无故障旗标）
- 运动结束后发 `?`，确认 STATE 回到 `IDLE`、且**静止时不主动发帧**（监听 1 秒应为 0 帧 —— 用 `?` 触发的那一帧除外）
